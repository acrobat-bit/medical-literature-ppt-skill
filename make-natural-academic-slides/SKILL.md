# 医学学术 PPT 制作与审阅

把材料、可编辑 PPTX、讲稿、来源和网页审阅连接为同一份可追溯成果。沿用用户已确定的听众、时长、语言和视觉方向；信息足够时直接执行。默认中文、16:9，采用 [Beamer Metropolis 初始模板](references/default-template.md) 的简洁学术样式。使用者指定的模板优先。页数按讲述任务确定，可从约 12 页开始规划。

## 表达方式

遵循 [直接表达与整套复核](references/language.md)：正文和讲稿直接陈述研究事实、关键比较与分析，网页说明直接交代操作。每次交付逐页阅读整套内容，再执行 `assets/language-policy.json` 的词项检查。对每句话明确其贡献：事实、解释、具体操作或演讲者填写引导。

## 读取与规划

读取用户材料和当前最新版 PPT，保留用户手工修改。按任务读取 [医学证据规范](references/evidence.md)、[视觉规范](references/visual.md) 和 [汇报结构](references/narratives.md)。

文献汇报先取得论文 PDF：优先接收使用者提供的文件；已给出题名、DOI、链接或选题方向时，自行查找并下载正式全文。文件与论文信息都缺少时，请使用者提供 PDF 或论文标识。核对题名、作者及文献身份后保存到材料目录。封面题名、论文图片和原表均从这份 PDF 提取或高清截取；补充材料使用对应的补充 PDF。作者照片和任职资料继续按作者介绍流程获取。

文献汇报采用 [文献汇报生成流程](references/literature-report.md)：第一页以可编辑文字显示文献的完整题名，原文题名截图作为补充图片，第二页采用“作者 / 简介”的两级标题，按 [作者介绍流程](references/author-profile.md) 仅介绍第一作者，展示其照片、任职与根据已发表论文归纳的研究领域。若完成检索后未找到第一作者其他可确认归属的著作，则改为介绍一位通讯作者。随后依次安排背景、方法、结果、讨论、亮点、局限和感想。用 `scripts/literature.py` 编排内容记录，`scripts/make_literature.mjs` 生成可编辑 PPTX。章节可有多页，按材料调整篇幅。用户另定结构时按用户要求制作。

封面采用左右结构：左侧依次放可编辑的完整文献题名、期刊、IF、演讲者和日期，右侧放原文题名图作为补充图片。IF 显示数据年份，从期刊官网或 JCR 核对数值并保存来源。省去底部文献信息小字。其余每页只设两级标题：大标题为两个汉字，如“背景”“方法”“结果”；小标题概括该页内容，如“对线精度”“研究流程”。正文采用连续段落。整套幻灯片省去新增的底部来源小字与页码，出处保留在备注、证据面板和来源索引。原文图表自带的图例、单位与脚注完整保留。

按 [文章亮点与讲述重点](references/highlights-and-emphasis.md) 先评价选题、方法、结论讨论和图表表达。新颖性按发表时已有研究比较，完成质量看具体设计与执行，图表美观、清晰度和信息组织单列为表达亮点。方法亮点明确比较既往做法与本文改进，重点识别新测量、设计、算法或统计思路；常规规范按基础方法讲述。选择 1–3 项主要亮点，落实到对应章节的篇幅与讲稿时间，并填写 focus_plan。讨论后依次设置独立的“亮点”“局限”“感想”页。

背景默认集中在一页，连接研究进展、尚待解决的问题与本文目的。根据听众知识判断术语解释的必要性，同行熟悉的术语直接使用；小标题直接写学术主题。方法交代研究流程、研究对象、干预、结局测量与统计分析。

先查论文 PDF 及补充 PDF 中的研究流程或患者入组图，PDF 内的图形摘要也纳入检查。找到原图时，从 PDF 提取或截取整图，以一张完整图片放在方法部分第一页，使用 source_full 版式居中展示；图下文字与讲稿说明人数对应的研究阶段。用户明确指定局部选取时，再按其范围裁切并记录。见 [原文素材流程](references/source-materials.md#研究流程图)。

结果正文提炼关键发现，给出必要的组间数值、效应量和时间点。原表提供完整数据，正文给出重要信息，讲稿补充解释与衔接。素材处理和计算过程放入证据记录。具体写法见 [文献汇报生成流程](references/literature-report.md)。

亮点和局限各默认一页，以 2–3 个连续段落适度展开，写清具体依据和解释后果，讲稿补充推理。

讨论连接主要发现与临床或研究意义；亮点总结研究的新意、完成质量与图表表达；局限说明具体问题对结果解释的影响。三部分都采用可直接讲述的连续分析，事实与解释逐项关联来源，具体规则见 [讨论与评价](references/literature-report.md#面向听众的讨论与评价)。

首页左侧的文字信息与右侧的补充截图分别排版；截图保留完整题名，演讲者和日期位于左侧下部。已提供的信息直接填写，其余位置使用可编辑空栏。

在工作目录建立 `deck.json`：每页保留稳定的 id、章节、标题、要回答的问题、内容、实际讲稿、论断与出处对应关系。格式见 [内容记录与运行](references/runtime.md)，可从 `examples/demo.json` 理解字段；演示数据标记为 `test_fixture`。

先定位关键数字、分析人群、分母、单位、时间点和图表，再组织叙事。核对文献身份与论断依据，保存原文位置及实际读取状态。补充检索使用原始论文或官方材料。

## 制作与渲染

使用当前环境的 Presentations 技能制作和导出 PPTX；它负责实际制作工具与文件检查。标题、正文和解释保留原生可编辑文字。文献图表统一使用从论文 PDF 提取的原图或原页截图，保留表头、坐标、图例和脚注。原文只以文字报告的数据，也以连续文字叙述。素材获取、截图与校验见 [原文素材流程](references/source-materials.md)。讲稿写入备注。

按 [高清原图与清晰度](references/source-materials.md#高清原图与清晰度) 提取 PDF 内嵌图片并保留原生像素；矢量图、原表和题名区默认按 600 dpi 截取。图片来源定位到 PDF 文件、页码及图像对象或截取范围，按最终放映尺寸检查文字与线条。网页检索用于取得 PDF，论文图表素材在 PDF 内完成获取。

将最终 PPTX 路径填入 `deck.json`，通过本技能的 `scripts/review.py render` 重新打开该 PPTX 并渲染。此操作绑定 PPTX 的 SHA-256、顺序和每页图片，网页显示该 PPTX 的实际渲染结果。

```bash
python3 <skill>/scripts/review.py render deck.json --out rendered
python3 <skill>/scripts/review.py validate deck.json
python3 <skill>/scripts/review.py build deck.json --out delivery
```

`<skill>` 是本文件所在目录。`render` 会更新内容记录中的渲染凭据路径，需在自己的工作副本上运行。命令参数、依赖与失败恢复见 [运行说明](references/runtime.md)。

## 按模板 PPT 改版

使用者提供模板 PPTX 或 POTX，并提出按模板修改时，直接执行 [模板改版流程](references/template-adaptation.md)。旧版 PPT 先通过 PowerPoint 另存为 PPTX。读取并逐页预览真实模板，按封面、作者、正文及原图页建立映射。导入和复制模板页面，替换对应的可编辑文字与原图，沿用模板的尺寸、字体、颜色、背景、母版和固定元素。模板中的示例内容通过映射明确替换或删除。

现有汇报先核对当前 PPT 与内容记录，合并使用者已做的修改。保持研究信息、图表来源及讲稿对应关系，使用新版本生成 PPT、网页预览、讲稿和来源索引。封面继续采用左侧题名、期刊、IF、演讲者和日期，右侧补充原图的结构。正文保留两级标题，长段落优先选用空间合适的模板版式。逐页对照模板，完成文字适配和原图清晰度检查后交付。

脚本 `scripts/template.mjs inspect` 输出全部模板预览、对象位置和映射骨架，`apply` 完成实际改版。使用者只需提供模板及改版要求，映射由执行 Skill 的助手完成。

## 网页审阅与修改

生成的 `delivery/index.html` 可直接离线打开，包含实际 PPTX 渲染图、章节与缩略导航、放大、讲稿、逐条证据、分项检查结果、逐页修改意见及成品下载。单个 HTML 已内嵌预览和下载文件，也可使用配套本地启动器。

意见存储在当前浏览器，导出 JSON 是可迁移备份；切换设备、浏览器或清除站点数据前需要导出。意见绑定文稿 id、版本和内容指纹。导入时核对版本和页面标识。

感想页提供选题方向与填写提示。用户只要求一个方向时，直接生成引导页。审阅台支持选择方向、自定主题和填写内容，自动保存并随修改清单导出。下一次生成使用演讲者实际填写的内容，并同步到 PPT 末页及讲稿。

网页负责记录和导出意见。用户交回修改 JSON/Markdown 后，核对版本，按稳定页 id 修改源内容和 PPT，同步讲稿与证据、递增版本、重新渲染、重新验收和交付。保留旧版及其意见，并记录新版本的生成状态。

## 验收与交付

按 [验收规范](references/acceptance.md) 分别记录证据、文件、视觉状态：`passed`、`issues`、`not_checked`。分别完成原文核对、文件检查和逐页看图。修改后复核受影响页面，将核查记录绑定到最终 PPTX 哈希。

交付可编辑 PPTX、审阅 HTML、逐页讲稿、来源索引和可再次生成的内容记录；按需附 PDF。打开审阅台实际测试导航、证据、放大和意见保存/导出，检查浏览器错误及窄屏布局。简要说明成果、使用方法和实际检查结果。

## 首次运行和维护

网页构建和校验仅需 Python 3.10+ 标准库。PPTX 渲染需要 Node 18+ 与 Codex 配套 `@oai/artifact-tool`；PDF 预览额外使用 Pillow。`doctor` 检查依赖，`tests/test_review.py` 验证关键不变量。`examples/make_demo.mjs` 与 `examples/demo.json` 提供采用演示数据的可编辑样张。

工作文件集中在当前任务目录，凭据由运行环境管理。默认交付本地成果；按用户指定的范围发布或共享。
