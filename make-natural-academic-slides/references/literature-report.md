# 文献汇报生成流程

先接收使用者的 PDF，或根据已知论文信息自行查找并下载正式全文。核对论文身份后，封面题名、正文图片和原表都从 PDF 获取，具体操作见 [PDF 素材流程](source-materials.md)。

## 标题与正文

封面采用左右结构，左侧依次显示可编辑的文献完整题名、期刊、IF、演讲者和日期，右侧放原文题名截图作为补充图片，省去底部文献信息小字。其余页的大标题只用两个汉字，按章节使用“作者、背景、方法、结果、讨论、亮点、局限、感想”，另设一个概括内容的小标题，如“对线精度”“研究流程”。正文使用连续段落，直接说明研究问题、步骤或结果。

首页的原文题名截图在右侧适度缩小，左侧下部留出演讲者与日期。第二页采用“作者 / 简介”，只介绍第一作者，著作检索与切换通讯作者的规则见 [作者流程](author-profile.md)。作者资料和相关发表也使用连续叙述。

## 先确定文章亮点

执行 [亮点判断与讲述重点](highlights-and-emphasis.md)，把新颖性、完成质量和图表表达分别评估。亮点在选题时重点展开背景中的证据缺口，亮点在方法时重点解释关键设计，亮点在结论讨论时充分讲清结果与意义，优秀的原图在对应结果页重点解读。按这些判断分配篇幅与讲稿时间。

## 内容结构

背景默认用一页串联研究进展、现有问题和本文目的，通常写成两个短段落。先按听众的专业背景判断哪些概念确实需要解释；骨科同行熟悉的 TKA、HKA 等术语直接使用，陌生且影响理解的概念在叙事中用一句话交代。小标题直接表达学术主题，例如“对线与临床获益”。只有多个独立且必要的研究问题确实需要分别展开时才扩展页数，优先压缩重复内容。涉及近期进展时补充检索原始研究并保留发表年份，说明它与当前论文的时间关系。

方法第一页用于研究流程。先检查论文 PDF、补充 PDF 与其中的图形摘要，找到研究流程或患者入组图时，在这一页插入一张完整原图；其余流程用连续文字讲述。对原图中的人数标明随机入组、完成随访或结局分析等阶段。随后按研究实际顺序介绍对象、干预、随访、结局测量和统计分析，保留主要纳排条件、主要与次要结局及样本量依据。

结果按主要终点和临床问题展开。原文表格作为原表截图呈现，图形使用原图，原文仅以文字报告的结果继续用文字说明。讨论、亮点和局限也采用完整段落。末页提供感想填写方向，由演讲者补充。

## 面向听众的结果表达

每页先确定听众应记住的一项发现，再选择支撑它的关键数据。正文采用“发现＋必要数值＋具体时间点或临床含义”的连续表述。比较结果保留组别方向、分母或分析人群、单位与原文报告的不确定性；内容拥挤时精简次要数字，完整数据仍在原表中。

例如，术前资料页可提炼人群以中老年患者为主、疾病程度及基线量表的重要特征；对线结果页直接说明达标率及绝对差；功能结果页直接说明随访时点的组间比较。统计学差异未达显著时，直接报告观察到的差值、区间或 P 值，结论对应研究实际采用的比较方法。

表格裁切、计算和校对过程写入来源与证据记录。结果正文和讲稿直接说明研究发现。数值冲突具体列出不同报告值及其解释影响。

定稿时逐页朗读结果正文，检查它是否回答了“发现了什么、差异多大、对当前问题意味着什么”，并回查来源。单纯列举指标名称或描述页面元素的句子应改写为研究信息。

## 面向听众的讨论与评价

讨论从最重要的发现出发，解释它回答了哪个问题、与其他结局怎样联系，以及对临床或研究意味着什么。把收益、代价和观察时间放在同一解释中，明确统计差异与临床意义的关系。机制和外推属于分析时使用相应措辞，并关联支撑该分析的事实；新增外部研究需实际读取和核对。

亮点采用“具体设计及其作用”的连续表述。例如，共同干预一致有助于减少哪些组间差异，独立测量有助于降低哪个环节的主观影响，样本量依据具体支持哪个终点。对多中心、随机和盲法，说明实际实施的环节及其对本研究证据的贡献，表述范围对应原文所报告的设计与结果。

局限采用“具体局限及其对结论的影响”的连续表述，优先选择最影响研究解释的内容。例如，随访长度界定结论覆盖的时间范围，样本量依据说明研究重点针对哪个终点，盲法安排影响哪些测量环节。登记问题直接交代入组、结局完成和登记的时间关系及其对预设方案公开追溯性的影响。报告冲突具体说明涉及的指标和解释后果。事实和分析连贯表达，去掉反驳式否定及泛化验证的尾句。

三类页面均直接给出分析内容。正文用短段落提炼核心判断，讲稿用完整口语化学术表达补足推理与衔接。资料处理和制作记录留在证据区；原文事实与汇报者分析分别保存为 evidence 的 claim、interpretation，派生数字保留 derivation。分析对应有依据的问题，演讲者的个人感想由本人填写。

定稿时朗读这三部分，逐段核对是否包含实质信息、明确推理和解释后果，检查它们与方法和结果的一致性。删掉只有设计标签、泛泛褒贬或重复结果数字的段落。

完成整套页面的 [表达复核](language.md#整套复核)，同时检查正文、讲稿和生成模板。统计数值优先采用原表精确值；使用近似值时注明计算方式并核对舍入结果。

## 编排与生成

工作目录保存 `brief.json`、`assets/` 和论文材料。`brief.json` 沿用 deck、sources，并包含 literature、body_slides。

`deck.style_policy` 默认是 `original_sources_two_levels`。除封面外，每页 `title` 为两字大标题，`subtitle` 为小标题，其他字段为 id、section_key、question、notes、evidence、expected_text、required_objects。question 是组织讲述的内部问题。新封面由编排器设置 `layout.title_mode: editable_title`，`title` 只作导航标识，`subtitle` 为空。新封面同时设置 `layout.cover_composition: split`。实际 PPT 的左侧以 `literature.paper_title` 为可编辑主标题，并显示期刊、IF、演讲者和日期，右侧放缩小的原文题名截图。旧版 `source_image` 记录保持兼容。

正文的 section_key 按 background、methods、results、discussion、advantages、disadvantages 顺序排列。编排器加入封面、作者页和感想页。

背景页使用 `background_coverage` 标明所讲内容，覆盖 progress、study_question 即可；概念解释按需加入，旧版 keywords 标记仍可保留。方法页使用 `method_coverage`，合计覆盖 workflow、participants、interventions、outcomes、statistics。这些标记用于验收完整性。

`literature.flow_diagram` 记录流程图检索结果：status 为 available 或 not_found，并记录 searched_locations。available 时填写 file，与方法第一页的 source_images 对应，且该页的 method_coverage 包含 workflow。新编排默认 display 为 whole_image，核对单张图片及完整显示；用户指定局部选取时使用 requested_crop。校验程序检查原图是否已放在方法首页。旧版记录沿用既有结构。

literature 字段包含 paper_source_id、paper_title、cover_title、cover_subtitle、cover_notes、cover_footer、title_capture，以及作者检索资料。cover_title、cover_topic 和 cover_subtitle 保留为内容元数据；新封面以 paper_title 呈现可编辑题名，题名截图作为补充。presenter 包含 name、affiliation、date；左右封面展示 name 与 date，未填写的信息显示可编辑空栏。reflection 可省略，使用现有填写引导。

## 原文图片与版式

图表来源字段及获取方法见 [原文素材流程](source-materials.md)。每页的 source_images 保存原图或截图记录，正文只使用 paragraphs。

| layout.kind | 用途 |
|---|---|
| prose | 连续段落，适合背景、方法、讨论、亮点、局限以及文字结果 |
| source_image | 一张原文图表，下方用短段落说明 |
| source_pair | 两张原图，下方用一个段落解释 |
| source_side | 左侧原图，右侧连续说明 |
| source_full | 一张完整原图居中，简短图注在下方；方法首页默认使用 |
| source_flow | 用户指定流程局部选取时，左图右文展示 |

source_full 遇到竖向流程图或多面板原图时，可设置 layout.orientation: portrait：完整原图在右侧占据较高画幅，左侧保留两级标题与连续说明。

paper_cover、authors、reflection 由编排器处理。旧版记录保留原有渲染路径；新文献汇报使用原图与两级标题模式。

```bash
python3 <skill>/scripts/literature.py brief.json --out deck.json
node <skill>/scripts/make_literature.mjs deck.json
python3 <skill>/scripts/review.py render deck.json --out rendered
python3 <skill>/scripts/review.py validate deck.json
python3 <skill>/scripts/review.py build deck.json --out delivery
```

`<skill>` 为安装目录。制作前遵循 Presentations 的操作记录、字体与文件检查要求。生成后检查每页原文图表的清晰度和完整性，确认封面题名可编辑、补充截图完整且底部文献信息小字已移除，其余页实际 PPTX 中恰有两级标题，且研究图表均为已登记的原始图片。

## 感想与后续生成

感想页用段落给出临床应用、研究设计或自己的课题等填写方向，讲稿同步为选题提示。已有 answers 时，讲稿按提示顺序使用实际填写内容。网页提供方向选择、主题填写和文本输入区；意见导出说明位于网页操作区。填写内容随修改清单导出，下一次生成写入 PPT 与讲稿，版本、页面 id、内容指纹和 PPTX 哈希保持对应关系。

## 使用提供的模板

收到模板后按 [模板改版流程](template-adaptation.md) 检查和适配，生成独立的新版本。封面、两级标题、连续段落、原图和作者规则继续生效。

## 期刊与 IF

literature.journal.name 保存期刊名称。impact_factor 保存 value、year、release_year、source_id、verified_at。year 为 JIF 数据年份，release_year 为 JCR 发布年份。先查询期刊官网或 JCR，核对数值与年份，再写入封面，例如“IF：84.5（2025 年）”。来源加入 sources，并关联封面 evidence。期刊信息留在左侧正文区。

## 页面底部

新记录默认 `deck.footer_policy: none`。整套页面省去新增的来源行、版权小字和页码，旧的 footer 与 cover_footer 字段可留作来源元数据。出处继续写入 PPT 备注及网页证据面板。原文图表内的图例、单位和脚注完整保留；新增图释若包含关键解释，移到讲稿或正文。网页预览下方省去制作说明小字。

新版本中的 advantages 和 disadvantages 继续作为稳定的章节键，显示标题分别使用“亮点”和“局限”。这两部分紧接在全部讨论页之后，随后为感想。
