# 直接表达与整套复核

用户要求简洁、具体、可直接向听众讲述的学术表达。正文写重要信息和分析；讲稿补充必要解释与自然衔接。每句话应提供研究事实、解释、具体操作或用户要求的填写引导。

## 写法

背景连接研究进展与本文问题。方法交代实际对象、流程、干预、测量和统计方案；用具体处理办法替代指向论文某处的空泛说明。结果直接报告发现和关键比较，按实际数值、单位、分母、时间点、区间及 P 值组织表达。

讨论解释发现的意义和取舍。优势说明设计怎样支持判断。不足把具体问题与其解释后果相连，例如登记时序影响公开追溯性，数值冲突影响效应大小的复核。分析只使用有依据的事实与联系。

删除反驳假想误读、免责、自我辩护和泛化验证要求。精简重复范围、重复限定及只介绍页面或素材的句子，把有用信息合并到具体事实中。论文中的研究问题、真实统计结果、设计局限和数值冲突按其实际内容表达。

来源、数据处理和制作过程保存在证据记录。讲稿直接讲研究内容。感想页提供演讲者选题与填写方向；填写后的讲稿使用演讲者实际输入的内容。

## 整套复核

逐页连读标题、正文和讲稿，检查每句话是否带来新信息，是否解释了发现或设计的重要性，以及是否出现反驳式、提醒式、空泛收尾或制作说明。按稳定页 id 记录改写或保留的结论，覆盖整套页面。

检查证据说明、作者资料、感想模板、网页提示及 Skill 中生成这些文字的默认内容。学术内容采用事实与分析，操作内容提供具体对象、动作和结果。将修改同步到生成器或模板，使后续生成沿用同一写法。

执行 `assets/language-policy.json` 的禁用词检查，再重新读取实际 PPTX 正文与备注。连读修改后的内容，核对统计信息、组别、时间点及原文含义。句子审阅与词项检查共同完成交付验收。

## 操作文字

交付说明写成果、位置与使用方法。版本和存储状态直接写事实，例如意见保存于当前浏览器、导出 JSON 用于迁移；出错时给出可执行的恢复操作。文献身份、读取状态和检查结果采用简短标签与具体记录。
